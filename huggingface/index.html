What this visualization can show
  • Which labeled PII categories occur in the embedded source-derived snapshot.
  • How those category labels vary by context type or locale.
  • Which available rows carry the supplied forget-set membership flag.
What it cannot prove
  • That a deployed AI trained on these rows.
  • That a deletion or unlearning procedure succeeded.
  • That a model will or will not reproduce any category in a future response.

What could an AI system do with this information?

These pathways connect the information represented in each dataset to documented benchmark operations or plausible analytical tasks. They describe an AI operation to investigate—not evidence that a model actually performed it on these records.

Evidence distinction: PrivacyLeak-PII directly benchmarks extraction, contextual inference, jailbreak attempts, and machine unlearning. Interpretation

How to read this comparison

The two datasets use different structures. PrivacyLeak-PII identifies PII categories within text records, while NHANES represents sensitive information as dataset columns. The percentages therefore describe representation in each available dataset; they are not directly equivalent privacy measurements.

The PrivacyLeak-PII dataset is a synthetic benchmark designed to study privacy leakage and machine unlearning. The local file used here is a snapshot rather than the complete Hugging Face dataset.

The comparison describes representation of sensitive information, not model memorization, model leakage, or successful machine unlearning.

Dataset attribution: raayraay/privacyleak-pii on Hugging Face. The local snapshot fields used by this page include sample_id, context_type, locale, is_canary, in_forget_set, pii_types, and pii_count.

Data-handling note: all observations embedded in this standalone page are source-derived public-viewer summaries. The page makes no network request, does not invent replacement values, and does not present these rows as evidence of real-world personal-data exposure.
